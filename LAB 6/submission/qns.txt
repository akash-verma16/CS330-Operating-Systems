Part1  
------

Q1. If you manually run the testcase#1 without performing any modifications, the OS hangs. Explain why?

The OS hangs because the excpetion handler returns 0 without doing anything. The PC remains at the div by zero instruction and tries to execute it again, which again raises an exception. 
Therefore, program gets stuck in infinite loop and OS hangs.

Q2. After building gemOS for testcase#1 (manually), run `objdump -D user/init.o`, examine the assembly for main to 
    find the `idiv' instruction. Apart from the implicit "rax" register, which other register is used? 
    Which registers is used as the numerator and which register as the denominator?

The instruction is:
  7a:	48 f7 f9             	idiv   %rcx

Therefore, the other register used is rcx. rcx is the denominator and rax is the numerator. This can be seen by the following instruction

70:	48 8d 48 ef          	lea    -0x11(%rax),%rcx

Here rcx stores rax - 17, which is what is being done in the program (den = num - 17).

Q1. After building gemOS for testcase#2 (manually), run `objdump -D user/init.o`, examine the assembly for main to 
    find the `idiv' instruction. What is the length of the `idiv' instruction?

The length of idiv is 3 = (7d - 7a). The instruction is given below.

7a:	48 f7 f9             	idiv   %rcx
7d:	48 89 45 f0          	mov    %rax,-0x10(%rbp)


Q2. Can we use the register over-writing strategy for testcase2? why or why not?
No, this is because a is written directly in the register (and not copied from the stack). As a result, when we overwrite a, it will also get overwritten in the main program.


Q3. Which memory does the `regs' argument to do_div_by_zero (in hack.c) point to (hint: check the os_rsp value in exec_ctx)?
The value of os_rsp is a bit above the the OS stack pointer. Therefore, it is stored in kernel stack.

Q1. What all registers are changed in do_div_by_zero and why?
base pointer (set to caller's base pointer)
stack pointer (set to caller's top of stack)
PC pointer (set to the instruction where the caller called the callee function);
rax register (the return value is stored in this)

Q2. In testcase #4 and #5, how many times the 'fact' function would return one? 

In testcase 4, three times one will be returned. one 1 will be returned normally for base case, the rest two would be due to div be zero errors in case of n = 3 and n = 5

Similarly, in test case 5 one will be returned five times. one 1 will be returned normally, and 4 1s will be returned due to div by zero errors in cases of n = 3, 5, 7, 9
